# Implementation Prompt: Phase 1 Foundation (Repo Setup)

## 1. Goal
Initialize the monorepo structure for Vibelearn and establish the core technology stack for both `frontend` (React + Vite + TailwindCSS + ESLint + Prettier) and `backend` (Node.js + Express + ESLint + Prettier), including `.env.example` templates and verifying both development servers start cleanly.

## 2. Skills & Guidelines Consulted
- **AGENTS.md**: Strict adherence to the roadmap, loop workflow, boundaries, technology lock (no TypeScript, no containerization, no unauthorized libraries), and prompt-first requirement.
- **Frontend Architecture (`docs/system_design/frontend.md`)**: Layered React architecture (components, pages, hooks, services, utils), exact folder structure, TailwindCSS setup, standard JavaScript only.
- **Backend Architecture (`docs/system_design/backend.md`)**: Layered Express architecture (routes -> controllers -> services -> repositories), exact folder structure, standard JavaScript only.
- **System Architecture & Database (`docs/system_design/architecture.md`, `docs/system_design/database.md`)**: Decoupled folders, environment variable stubs for Clerk and Supabase, port assignments.
- Note: Superpowers skills excluded per user instruction.

## 3. Code & Config Inspected
- Current workspace root contains only `.git`, `AGENTS.md`, and `docs/`.
- No existing `frontend` or `backend` code or configuration files exist.
- System Node.js version is `v22.23.1`.

## 4. Decisions & Assumptions
1. **JavaScript Only:** In strict compliance with `docs/system_design/architecture.md` line 35, both `frontend` and `backend` will be written in standard JavaScript (`.jsx` for React, `.js` for Node). No TypeScript.
2. **Standard Folder Structures:**
   - `frontend/`:
     ```
     frontend/
     ├── src/
     │   ├── assets/
     │   ├── components/
     │   ├── pages/
     │   ├── hooks/
     │   ├── services/
     │   ├── utils/
     │   ├── App.jsx
     │   ├── index.css
     │   └── main.jsx
     ├── public/
     ├── index.html
     ├── tailwind.config.js
     ├── postcss.config.js
     ├── vite.config.js
     ├── eslint.config.js
     ├── .prettierrc
     ├── .env.example
     └── package.json
     ```
   - `backend/`:
     ```
     backend/
     ├── src/
     │   ├── config/
     │   ├── db/
     │   ├── middlewares/
     │   ├── routes/
     │   ├── controllers/
     │   ├── services/
     │   ├── repositories/
     │   └── index.js
     ├── drizzle.config.js
     ├── eslint.config.js
     ├── .prettierrc
     ├── .env.example
     └── package.json
     ```
3. **TailwindCSS Version & Setup:** Standard TailwindCSS v3 setup with `tailwind.config.js` and `postcss.config.js` matching `docs/system_design/frontend.md`.
4. **Backend Dev Server Runner:** Since Node 22 natively supports `--watch`, backend dev server will use `node --watch src/index.js` without requiring external watchers like nodemon, keeping dependencies minimal.
5. **Port Allocation:** Frontend will run on Vite's default `5173`, Backend will run on `5000`.

- Database credentials and Clerk Secret Key MUST remain strictly in `backend/.env.example` (as stubs) and never be placed in `frontend`.
- No sensitive real API keys or DB passwords will be committed.
- CORS on backend will be configured to accept requests from the frontend origin (`http://localhost:5173`).
