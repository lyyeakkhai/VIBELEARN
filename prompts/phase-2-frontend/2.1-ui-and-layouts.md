# Implementation Prompt: Phase 2 Frontend First (UI & Layouts)

## 1. Goal
Build the complete, production-grade frontend user interface for Vibelearn using React (Vite), TailwindCSS, and Clerk React SDK with comprehensive mock data modeled after `docs/seed.ndjson` and `docs/videos.json`, strictly reproducing the design mockups in `docs/design/` across all 5 pages:
1. Home Page (`home-page.png`)
2. Public Catalog & Search Page (`course-page.png`)
3. Course Detail Page (`detail-page.png`)
4. Lesson Page (`learning-page.png`)
5. My Learning Dashboard

## 2. Skills & Guidelines Consulted
- **AGENTS.md**: Strict loop workflow, prompt approval gate, technology boundary (no direct DB connection from frontend, no TypeScript, no containerization, no authoring UI, no custom video players, YouTube embed only, Clerk for auth).
- **Frontend Architecture (`docs/system_design/frontend.md`)**: Layered React architecture (`pages/`, `components/`, `hooks/`, `services/`, `utils/`), no inline API calls in components, keep components modular (< 150 lines), mobile-first responsive styling with Tailwind.
- **Backend & Database Contracts (`docs/system_design/backend.md`, `docs/system_design/database.md`)**: Align mock data schema with the database tables (`courses`, `modules`, `lessons`, `progress`, `users`) so swapping mock data for API in Phase 4 is seamless.
- **Design System Specifications (`docs/design/design-system.png`)**: Strict palette (Primary 500: #10B981, Neutral 900: #0F172A), Typography (Playfair Display for display titles, Inter for headings & body), Spacing base unit (4px), Radii (4px, 8px, 12px, 16px, 24px, full), Shadows (sm, md, lg, xl), and Buttons/Badges.
- Note: Superpowers skills excluded per user instruction.

## 4. Decisions & Assumptions
1. **Design System Source of Truth (`DESIGN.md`):** Formalize `docs/system_design/DESIGN.md` using the exact specifications from `docs/design/design-system.png` (Color codes, typography scale, spacing, elevation shadows, component specs).
2. **Typography & Styling:**
   - Load `Playfair Display` (weights 600, 700) and `Inter` (weights 400, 500, 600, 700) via Google Fonts in `frontend/index.html`.
   - Extend Tailwind theme with `fontFamily.serif` / `fontFamily.display` (`Playfair Display`) and `fontFamily.sans` (`Inter`), full `primary` and `neutral` color scales, border-radius tokens, and elevation shadows.
3. **Routing:**
   - Use `react-router-dom` for declarative client-side routing.
   - Routes:
     - `/`: Home page (`home-page.png`)
     - `/courses`: Catalog & Search results (`course-page.png`)
     - `/courses/:slug`: Course Detail (`detail-page.png`)
     - `/courses/:courseSlug/lessons/:lessonSlug`: Lesson Player & Notes (`learning-page.png`)
     - `/my-learning`: My Learning Dashboard (Protected)
4. **Authentication with Clerk (following official Clerk best practices):**
   - Linked to Clerk application: `app_3JLl4RmNvKVxutedBaHT0gDMr6x`.
   - Setup with Clerk CLI (`clerk init --app app_3JLl4RmNvKVxutedBaHT0gDMr6x`) or install official `@clerk/clerk-react` in `frontend/`.
   - Setup `ClerkProvider` in `frontend/src/main.jsx` with `publishableKey` read from `import.meta.env.VITE_CLERK_PUBLISHABLE_KEY`.
   - Implement clear auth controls visible in layout navigation:
     - When signed out: `<SignInButton mode="modal">`, `<SignUpButton mode="modal">`
     - When signed in: `<UserButton afterSignOutUrl="/" />`
   - Protect `/my-learning` using `<ProtectedRoute>` with Clerk `<SignedIn>` / `<RedirectToSignIn>` or interactive sign-in callout.
   - Run `clerk doctor` / verification to ensure environment keys and provider setup are valid.
5. **Iconography:**
   - Provide a clean, unified SVG icon library (`components/ui/Icons.jsx`) with 24x24 viewBox, 2px stroke width, matching the exact outline and filled icon style from `design-system.png` (Check, Play, ArrowRight, Book, Clock, Users, Bell, Search, ExternalLink, Bookmark, Code, Sparkles, Layers, etc.) with zero extraneous dependencies.
6. **YouTube Video Embed:**
   - Standard 16:9 responsive YouTube embed (`https://www.youtube-nocookie.com/embed/{videoId}`) on the Lesson Page matching PRD requirements (no custom player, no off-site redirects).
7. **Mock Data Quality:**
   - Ground `frontend/src/data/mockData.js` directly in the content from `docs/seed.ndjson` and `docs/videos.json`, ensuring realistic courses, modules, lessons, video IDs, student counts, and rich lesson notes.

## 7. Security Considerations
- Keep Clerk publishable key in `VITE_CLERK_PUBLISHABLE_KEY`.
- No Clerk secret keys or backend database connection strings allowed in frontend.
- Safe fallback if Clerk keys are absent so developers can inspect and test UI without crashing.
- Embed YouTube videos using privacy-enhanced `youtube-nocookie.com` domain with appropriate `allow` attributes (`accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture`).
